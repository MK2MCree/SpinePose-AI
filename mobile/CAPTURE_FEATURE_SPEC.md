# 脊见智诊：引导拍摄与本机图片记录

更新日期：2026-10-24。状态：0.2.0 已实现，真实鸿蒙编译通过，44 项本地行为测试通过，尚待设备验收。

本次需求是给现有单机记录工具增加两个入口：**引导拍摄、选择本机图片**。图片、来源、视角和本地文件信息一起保存到用户自己的记录表中。应用不联网，不调用模型。

## 使用流程

1. 在新增或编辑记录中添加图片。
2. 选择“引导拍摄”或“选择本机图片”。
3. 选择照片视角：正面、侧面、背面、斜侧面；普通选图也可以标为“其他”。
4. 拍摄前查看简短提示，再打开系统相机拍照；选择图片则打开系统图片选择器。
5. 返回应用后查看缩略图，确认图片及视角；可移除并重新添加。
6. 保存记录。图片复制到应用自己的文件目录，记录保存对应文件名、来源、视角和时间。

引导位于应用的拍前页面。系统相机取景器由系统提供，当前版本不宣称能在其内部叠加自定义人体轮廓或实时判断。

## 拍前提示

| 视角 | 简短提示 |
| --- | --- |
| 正面 | 面向镜头，保持自然站姿，让身体需要记录的部分完整入镜。 |
| 侧面 | 让身体一侧朝向镜头，保持手机平稳。 |
| 背面 | 背对镜头，建议请他人协助，或固定手机后拍摄。 |
| 斜侧面 | 身体自然转向斜侧，确认没有明显遮挡后拍摄。 |

各类提示只是帮助用户构图，不做识别、评分或自动纠正。可以跳过某个视角，也不要求四张都拍齐。

## 记录展示

- 每条记录最多保存 4 张图片。
- 每张图片展示缩略图、视角和来源（拍摄 / 本机选择）。
- 可以查看图片在应用内的本地保存路径。
- 可以新增、移除或替换图片，保存后与文字记录一起保留。
- 图片不存在时显示明确提示，不显示成已成功加载。
- 普通图片记录允许时长为 0，不要求为了保存图片填写活动分钟数。

用户说的“上传图片路径”在本版本指**从手机选择图片并记录其本地保存位置**。不会向服务器上传文件。

## 本地文件处理

系统选择的图片立即复制到应用私有的 `record-photos` 目录，避免只保留临时选择路径。文件名由应用生成，原文件名作为显示信息保存，不以用户输入的路径读写文件。

单张图片上限为 20 MiB。选择后应实际检查能否解码为图片；取消、损坏、超限或保存失败时，不添加假附件，已有文字和其他图片继续保留。

拍摄或选择成功后，尚未保存记录的图片属于草稿附件。放弃草稿时清理这些新文件；编辑时移除的旧图片要等记录成功保存后再清理。删除记录或清空记录后，清理已不被其他记录引用的图片。

应用只清理自己 `record-photos` 目录中的文件，不删除相册或用户原始文件。

## 记录表与 JSON 备份

JSON 导出包含文字记录及图片元数据，不包含图片二进制内容。导出界面和导入提示需明确这一点。

图片附件最少保存：附件 ID、应用生成的本地文件名、来源、视角、原文件名、添加时间。完整显示路径在本机按应用目录生成。

在另一台设备导入 JSON 后，如果对应图片文件不在本机，保留记录并显示“图片文件不在本机，请重新选择”，不能承诺仅凭 JSON 就恢复照片。卸载或清除应用数据会删除应用保存的记录和图片，用户相册中的原图不受应用清理操作影响。

## 验收项目

- 现有活动记录可正常打开、修改和保存，旧 JSON 文件仍可导入。
- 四种拍前引导均能进入系统相机；返回后来源和视角正确。
- 从本机选图后能预览、保存，重启应用后仍可查看图片和路径。
- 取消相机或图片选择，不影响已有草稿内容。
- 相机不可用、模拟器不支持拍摄、图片损坏或超限时给出提示，并保留草稿。
- 编辑时移除旧图后放弃修改，原记录及其图片仍存在。
- 替换、删除和清空只清理不再被引用的应用内副本。
- JSON 备份保留图片元数据；缺少图片文件时有占位提示。
- 模拟器检查页面与取消/错误流程；实际成像和系统图片选择仍需真机确认。
